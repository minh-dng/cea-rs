# GitHub source, CI and release artifacts

[minh-dng/cea-rs](https://github.com/minh-dng/cea-rs) is the canonical source.
The original [GitLab project](https://gitlab.com/keplr-space/cea-rs) and package
registry are retained. The migration imported main at
`10d72251aff770348f66f5ee73a9fb3a292053f1` and the original `v0.1.0a1` and
`v0.1.0a2` tag objects without rewriting history. Existing registry packages,
scientific evidence and numerical goldens are unchanged.

Before public import, all 18 reachable commits and 117 unique file blobs were
inventoried. Gitleaks 8.30.1 found no matches in history or the complete blob
inventory. No binary artifacts, credential paths or tracked AppleDouble files
were present. NASA's database and license, the retained NASA notice, and both
Bit Mango license pairs were checked against the pinned upstream sources in
[provenance](provenance.md). This audit does not establish scientific validity.

## CI

[CI](../.github/workflows/ci.yml) runs for pull requests and main:

- Rust 1.99.1: `cargo test --locked` and Clippy with Python features and warnings
  treated as errors.
- Maturin 1.15.0: release wheels for Linux x86-64, Linux ARM64 (the Keplr target),
  and macOS ARM64, using native runners. Linux wheels target manylinux 2.28.
- Each wheel is installed into a separate directory and the existing three
  installed-wheel tests run outside the checkout on Python 3.12 and 3.15.1.
- The Linux x86-64 job also builds the source distribution. Successful jobs
  retain their artifacts in GitHub Actions.

The GitLab CI configuration now prevents legacy pipelines. GitLab CI is also
disabled for this project only. [Historical CI evidence](ci-validation.md)
remains unchanged and is separate from actual GitHub run results.

## Future alpha releases

After review and merge, bump both Cargo and Python package versions before
creating a matching `v<python-version>` tag on main. The
[release workflow](../.github/workflows/release.yml) rejects versions 0.1.0a1
and 0.1.0a2 and tags whose version or main ancestry does not match. It reruns
the complete CI, then creates a GitHub prerelease containing the three tested
wheels, source distribution and `SHA256SUMS`. An existing GitHub release is
never overwritten. Stable releases will need an explicit change to the
prerelease policy.

This workflow uses the automatic repository token only. It does not publish to
PyPI, crates.io or GitLab, and it does not deploy Keplr. No deployment or package
publishing secret is required. The preserved old tags have no GitHub release
artifacts generated by this migration; consumers pinned to 0.1.0a2 continue to
use their existing registry artifacts and hashes.
